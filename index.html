    El modelo TCP/IP frente a OSI

    El modelo OSI tiene 7 capas teóricas; TCP/IP, el que realmente usa Internet, las agrupa en 4 (o 5 si separamos física y enlace). En este laboratorio seguimos la numeración OSI (capa 2, 3, 4…) porque es la que se usa en el día a día ("un switch de capa 2", "un balanceador de capa 7").

    ¿Qué es un network namespace?

    Un network namespace (netns) es una copia aislada de la pila de red del kernel de Linux. Cada netns tiene sus propias interfaces, direcciones IP, tabla de rutas, tabla ARP, reglas de iptables y sockets. Para nosotros, cada netns es un "ordenador" virtual, pero sin el coste de una máquina virtual: comparten el mismo kernel y el mismo sistema de ficheros.

    Para "cablearlos" usamos interfaces veth (virtual ethernet): siempre se crean por parejas, como los dos extremos de un cable. Lo que entra por un extremo sale por el otro. Para hacer un switch usamos un bridge de Linux.

    Todo funciona con sudo. Crear namespaces necesita privilegios de root. Puedes escribir sudo delante de cada comando (como en esta web) o abrir una consola de root con sudo -i y quitarlo. Tu conexión real a Internet no se ve afectada: todo vive en namespaces separados.

    Primeros pasos con ip netns

    Antes de empezar las capas, juega un minuto con los comandos básicos:

    host
    # Crear un namespace llamado prueba
$ sudo ip netns add prueba
# Listar los namespaces que existen
$ ip netns list
# Ejecutar un comando DENTRO del namespace
$ sudo ip netns exec prueba ip link
# Abrir una consola entera dentro del namespace (sales con exit)
$ sudo ip netns exec prueba bash

    Verás que solo existe la interfaz lo (loopback) y que además está apagada (state DOWN):

    1: lo: <LOOPBACK> mtu 65536 qdisc noop state DOWN mode DEFAULT group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    host
    # Encender el loopback y probarlo
$ sudo ip netns exec prueba ip link set lo up
$ sudo ip netns exec prueba ping -c 2 127.0.0.1
# Borrar el namespace (borra también sus interfaces)
$ sudo ip netns del prueba

    Truco para no perderte: abre una terminal por cada "ordenador" y entra en él con sudo ip netns exec pc1 bash. Así cada ventana es un equipo distinto. Para saber en cuál estás, ejecuta ip netns identify.

    Cómo leer esta guía

    • La etiqueta encima de cada bloque indica dónde se ejecuta: host (tu Arch normal), pc1, pc2, r1… Cuando dice pc1 se asume que el comando se lanza con sudo ip netns exec pc1 … (lo escribimos completo en las primeras secciones de cada capa).
    • Las líneas en gris que empiezan por # son comentarios; el botón copiar los quita.
    • Los bloques punteados son la salida esperada (puede variar ligeramente en tu equipo: las MAC aleatorias, los tiempos…).
    • Cada capa empieza desde cero. Al final de cada laboratorio está el comando para borrarlo.
    • Usamos MAC fijas tipo 02:00:00:00:00:01 (el bit "02" indica dirección administrada localmente) para que los resultados sean fáciles de leer.
